# 株スクリーナー

日本株と米国株を対象にした、個人用の株スクリーナーです。

- 逆張りモード: TOPIX Core30 + Large70 ／ S&P 100
- 順張りモード（ミネルヴィニ式）: TOPIX 500 ／ S&P 500
- ファンダ分析（5軸のレーダーチャート）: TOPIX 500 ／ S&P 500
売買の自動執行はしません。判断材料を表示するだけです。

**このサイトは投資助言ではありません。最終判断は自己責任で行ってください。**

## 仕組み

1. GitHub Actions が毎営業日の引け後に株価を取得し、判定結果を `docs/data/` の JSON に保存します。
   - 日本株: 平日 16:30 JST（予備 18:30）
   - 米国株: 火〜土 7:30 JST（予備 9:30）
2. 財務データは週1回（土曜 11:00 JST）取得し、`data/` に保存します。PER など株価で変わる指標は毎日計算し直します。
3. GitHub Pages が `docs/` を公開します。画面は JSON を読んで表示するだけです。
4. ポジションやトレード記録は、見ている端末のブラウザの中にだけ保存されます（このリポジトリには入りません）。

## フォルダ

| 場所 | 内容 |

| `config/universe_jp_momentum.csv`, `universe_us_momentum.csv` | 順張りの対象銘柄 |
| `screener/` | 判定ロジック（市場に依存しない）。順張りは `momentum.py`、ファンダ分析は `fundamentals.py` |
| `markets/` | 市場ごとの違いとデータ取得 |
| `scripts/update.py` | データ更新（毎日） |
| `scripts/update_fundamentals.py` | 財務データの取得（週1回） |
| `scripts/run_backtest.py` | バックテスト（手動で実行） |
| `screener/forward.py` | シグナルの自動追跡（フォワードテスト） |
| `screener/regime.py`, `sectors.py`, `events.py`, `notify.py` | 相場環境・セクター強弱・イベント・通知の文面 |

| `scripts/build_universe.py` | 銘柄リストを公式の構成銘柄から作り直す |
| `docs/` | 公開される画面とデータ |
| `tests/` | テスト |

## よく使う操作（ターミナルで、このフォルダに移動してから）

```
# 最初の1回だけ: 作業用の環境を作る
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m playwright install webkit

# テスト
.venv/bin/python -m pytest -q

# 手元でデータを更新（--force で作り直し）
.venv/bin/python scripts/update.py --market jp
.venv/bin/python scripts/update.py --market us

# 手元で画面を見る → ブラウザで http://localhost:8000
python3 -m http.server 8000 --directory docs

# 銘柄の入れ替えを反映（momentum を付けると順張り用）
.venv/bin/python scripts/build_universe.py jp
.venv/bin/python scripts/build_universe.py jp momentum
```

## しきい値を変えるには

`config/thresholds.yaml` を書き換えて保存し、GitHub に反映（push）します。次のデータ更新から新しい値で判定されます。
「仮置き」と書いてある値は、バックテスト（フェーズ4）で見直す前提のものです。

## 順張りモードについて

- トレンドテンプレート8条件、相対強度（RS）、VCP を判定します。しきい値は `config/thresholds.yaml` の `momentum:` にあります。
- チャート用のデータと決算日は、8条件すべてに合格した銘柄だけ作ります（リポジトリが大きくなりすぎないようにするため）。
- 順張りの更新に失敗しても、逆張りの結果は保存されます。

## ファンダ分析について

- 割安度・成長・過去実績・財務健全性・配当の5軸を、それぞれ6項目のチェックで採点します。しきい値は `config/thresholds.yaml` の `fundamentals:` にあります。
- 割安度は他の銘柄との比較で、理論株価（DCF）の計算はしていません。成長はアナリスト予想にもとづきます。
- 銀行・保険などの金融業は、財務健全性などの一部の項目を判定しません。
- 点数は参考情報で、逆張り・順張りの候補判定には使っていません。
- 財務データを手元で取り直すには: `.venv/bin/python scripts/update_fundamentals.py --market jp` のあと `.venv/bin/python scripts/update.py --market jp --mode fundamentals`

## バックテストについて

- 過去10年の日足で、各サインが出たあとの成績を集計します。結果は画面の「検証結果」で見られます。
- 自動では実行しません。しきい値を見直したいときに手元で実行します（1市場あたり3〜4分）。
  ```
  .venv/bin/python scripts/run_backtest.py --market jp
  .venv/bin/python scripts/run_backtest.py --market us
  ```
- 古い8年でしきい値を選び、直近2年で通用するかを確かめる、という見方をします。しきい値は自動では書き換えません。
- 限界: 今の構成銘柄だけで検証しているため、成績は実際より良く出ます。手数料・税金・売買時の価格のずれも含みません。

## 資金管理・成績分析（フェーズ5）

- 「保有・記録」に「保有・記録 ／ 成績 ／ 資金設定」の切り替えがあります。
- **資金設定**: 運用資金（円・ドル）と、1回の取引で許容する損失の割合（初期値1%）。円とドルは円に換算して合計します。
- **株数の計算機**: 銘柄の詳細画面と登録画面にあります。損切り価格の候補（−3σ、買値の−7%、順張りは−8%と50日線）から、買ってよい株数・必要資金・損切り時の損失を出します。日本株は100株単位です。
- **全体リスク**: 全部が損切りになった場合の合計損失、市場・セクター・テーマ別の配分、集中と信用建玉の警告。
- **成績**: 勝率・損益比・期待値・R倍数などを、買った理由・市場・逆張り／順張り・月・ルール違反の有無で集計し、指数（日経平均・S&P 500）と比べます。
- しきい値は `config/thresholds.yaml` の `sizing:` と `stats:` にあります（すべて仮置き）。
- **資金額・保有・売買記録・損益は、見ている端末のブラウザの中にだけ保存されます。** このリポジトリや GitHub Actions には入りません（`tests/test_privacy.py` で確かめています）。エクスポートしたファイルには含まれるので、そのファイルはリポジトリに入れないでください。

## シグナルの自動追跡（フォワードテスト）

- 毎日のデータ更新で、その日に出たシグナル（逆張りのエントリー候補・警戒サイン、順張りのブレイクアウト）を記録し、以後の更新で5・10・20営業日後の騰落率、同じ期間の指数の騰落率、出口ルールどおりに売った場合の結果を埋めます。結果は「検証結果」ページの「実運用での成績」で見られます。
- 追跡開始は 2026年11月13日（終値）です。
- 保存先は `docs/data/forward/` です。
  - `{市場}_{年}.json`: シグナルの履歴。1行に1件、年ごとにファイルを分けるので大きくなりにくい（1市場で年に数百KBの見込み）
  - `{市場}_versions.json`: しきい値設定の番号と中身。判定に関わるしきい値を変えると番号が変わり、変更前のシグナルとは分けて集計します
  - `{市場}_summary.json`: 画面用の集計
- 件数が `forward.min_samples`（仮置き30件）に届くまでは「まだ判断できない」と表示します。
- 追跡に失敗しても、ほかのデータ更新は保存されます（Actions の画面に警告が出ます）。

## 相場環境・セクター強弱・カレンダー・通知（フェーズ6）

- **相場環境**: 逆張り・順張りの一覧の上に「逆張り向き／順張り向き／様子見」を、根拠の数値と推移グラフつきで表示します。順張りの対象銘柄（約500銘柄）の「25日線・200日線より上の割合」「52週高値・安値の更新数」と、指数・VIX から毎日判定します。基準は `config/thresholds.yaml` の `regime:`（仮置き）。環境と合わない候補には「今の環境とは逆」と表示します（候補は消しません）。
- 相場環境別のバックテスト（検証結果ページ）は、基準を見直すときに手元で実行します（1市場あたり数分）:
  ```
  .venv/bin/python scripts/run_regime_study.py --market jp
  .venv/bin/python scripts/run_regime_study.py --market us
  # 判定基準を変えた場合の比較（基準は自動では変えない）
  .venv/bin/python scripts/run_regime_sweep.py --market jp
  .venv/bin/python scripts/run_regime_sweep.py --market us
  ```
- **セクター強弱**: 「セクター」タブ。セクター・テーマごとの1週間・1か月・3か月の指数との差、順位の変化、25日線より上の割合。米国株は公式のセクターETF（XLK など）の値も並べます。「見るだけ」ラベルと、一覧の「強いセクター・テーマ」絞り込みはこの集計を使います。基準は `sectors:`。
- **イベントカレンダー**: 「カレンダー」タブ。SQ・米国のオプション満期日・日米の休場日は自動計算。FOMC・日銀会合・CPI・雇用統計は `config/events.yaml` に、公式サイトで確認した日程を出典・確認日つきで書きます（**年に1回、公式サイトを見て更新**。期限が近づくと画面と Actions に警告が出ます）。
- **通知（Discord）**: 毎日のデータ更新で新しい営業日のデータができたら、市場ごとに1通送ります。内容は相場環境の切り替わり・VIX が基準を超えた日（米国株）・新しいエントリー候補とブレイクアウト・次の営業日の重要イベント・ウォッチリスト。設定は `notify:`（市場ごとのオン／オフ、内容がない日も送るか）。
  - 送り先は GitHub Secrets の `DISCORD_WEBHOOK_URL`、ウォッチリストは Secrets の `WATCHLIST`（例: `jp:7203, us:AAPL`）。どちらもリポジトリには書きません。
  - 手元で文面を確かめる: `.venv/bin/python scripts/notify.py --market jp --dry-run`

## 需給メモ（フェーズ7）

- 信用残・空売り比率・投資部門別などの需給データは、無料の取得元の利用規約で自動取得や再配布が認められていない（または確認できない）ため、自動では取得しません。
- 代わりに、自分で公式サイト（日本取引所グループなど）を見て数字を入力する「需給メモ」があります。日本株のみ。
  - 市場全体（逆張りの一覧の上）: 空売り比率（日次）、投資部門別の売買差額（週次）→ 推移グラフ、「高い」「急上昇」の表示
  - 個別銘柄（銘柄の詳細）: 信用買い残・売り残（週次）→ 信用倍率と推移、「戻り売りが出やすい」「買い戻しが入りやすい」の表示。一覧で「需給メモあり」の絞り込みと「信用倍率が低い順」の並べ替え
- 入力した値は見ている端末のブラウザの中にだけ保存されます（エクスポートには含まれます）。リポジトリ・GitHub Actions・通知には出しません。
- 基準は `config/thresholds.yaml` の `supply:`（仮置き）。候補の判定・相場環境の判定には使っていません。

## データについて

- 株価・指数・VIX・為替・決算予定日・財務データ・アナリスト予想は Yahoo Finance（yfinance 経由、非公式）。遅れや誤りを含むことがあります。
- 取得元のデータには、株式分割が過去の株価に反映されていない・値が壊れている、といった異常がまれにあります。そうした「断絶」より前の履歴は使いません（`markets/fetch.py` の `drop_before_break`）。
- 日経VI と Fear & Greed は自動取得していません。画面で手入力します。
- チャートは TradingView Lightweight Charts（Apache License 2.0）を同梱しています。
